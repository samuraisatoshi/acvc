# Bonnes pratiques

Écrivez la croyance avec les mots d'une personne. Gardez chaque tentative. Un nombre pire n'efface pas la tentative, et n'écrit pas le motif à votre place.

- La prémisse est le problème dans la langue d'une personne. Le hash n'est pas le nom de l'hypothèse.
- Chaque cause reste sur l'hypothèse qui la suppose. Plusieurs causes ne deviennent pas une seule phrase de campagne.
- `context` est la première lecture de la session. `frontier` répond à ce qui est encore en concurrence. `why` répond à une hypothèse.
- Enregistrez un essai complet pour chaque métrique du schéma. La frontière ignore un essai incomplet.
- Laissez le pire essai dans l'historique. Il documente la tentative.
- Rejetez seulement avec un motif écrit par celui qui a décidé. La dominance n'est pas la mort.
- Utilisez `.acvcignore` dans le dossier semé pour ce qui n'est pas l'hypothèse. Ne comptez pas sur le `.gitignore` de Git.
- Le store suit `--repo`. Les marqueurs restent dans le dossier semé.
- Montrez la prémisse, le statut et la métrique. Montrez le hash seulement quand l'agent doit passer l'identifiant à une autre commande.
- `recall` avec un mot de la prémisse, accent compris. Une recherche vide, ou faite seulement de ponctuation, est une erreur.
- `spend` enregistre ce que la session a réellement consommé. Ce n'est pas un budget, pas une métrique, et cela ne bloque pas `record`.
- La page, la TUI, VS Code et Obsidian parlent déjà en prémisse. Ne rouvrez pas SQLite pour « améliorer » le visualiseur.
