# Mau uso

- Abrir `.acvc/graph.sqlite`, `objects.log` ou `objects.pack` para ler status, fronteira ou premissa. O contrato é o executável.
- Tratar o Git como o grafo de hipóteses. O commit não guarda o ensaio perdedor nem o motivo que não foi escrito.
- Segundo `seed` na mesma campanha. A campanha já tem origem. O caminho é `record` a partir do pai.
- Rejeitar porque outra hipótese dominou. Isso grava um motivo que ninguém deu.
- Fundir duas hipóteses incomparáveis, ou religar seeds soltos, para a fronteira ter um único vencedor.
- Usar `spend` como orçamento, métrica da fronteira ou trava de `record`. Inventar um número de tokens.
- Achar que o último `score` apaga o anterior, ou misturar `tests_passed` de um ensaio com `latency_ms` de outro.
- Ler `.gitignore` como política da varredura. A política explícita é `.acvcignore`.
- Hardlink entre árvores. Symlink dentro da pasta semeada.
- `promote` como merge, ou `push`/`fetch` esperando checkout do outro lado.
- Mostrar hash, aresta ou “left/right” para a pessoa. A frase é a premissa e quem fica.
- Colar todas as causas numa única necessidade da campanha quando há mais de uma causa no grafo.
- Reescrever uma hipótese já gravada para “corrigir” a premissa. Premissa nova é `revise_premise` ou `record`, outro nó.
- Subir `acvc web` ou `acvc tui` de dentro da sessão do agente quando a pessoa já tem o visor aberto. Diga o comando para o terminal dela.
