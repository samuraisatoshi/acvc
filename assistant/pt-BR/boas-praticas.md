# Boas práticas

- A premissa é o problema em linguagem de pessoa. O hash não é o nome da hipótese.
- Cada causa fica na hipótese que a assume. Várias causas não viram uma frase única da campanha.
- `context` é a primeira leitura da sessão. `frontier` responde o que ainda compete. `why` responde uma hipótese.
- Grave ensaio completo para todas as métricas do esquema. A fronteira ignora ensaio incompleto.
- Deixe o ensaio pior no histórico. Ele documenta a tentativa.
- Rejeite só com motivo escrito por quem decidiu. Dominância não é morte.
- Use `.acvcignore` na pasta semeada para o que não é a hipótese. Não conte com o `.gitignore` do Git.
- O store segue `--repo`. Os marcadores ficam na pasta semeada.
- Mostre a premissa, o status e a métrica. Mostre o hash só quando o agente precisa passar o identificador a outro comando.
- `recall` com uma palavra da premissa, inclusive com acento. Uma busca vazia ou só com pontuação é erro.
- `spend` registra o que a sessão de fato consumiu. Não é orçamento, não é métrica e não bloqueia `record`.
- Página, TUI, VS Code e Obsidian já falam em premissa. Não reabra o SQLite para “melhorar” o visor.
