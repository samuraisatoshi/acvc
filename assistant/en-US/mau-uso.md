# Misuse

These are the ways the record stops meaning what it says. Failed attempts stay here. Git receives only the attempt a person approves.

- Opening `.acvc/graph.sqlite`, `objects.log`, or `objects.pack` to read status, frontier, or premise. The contract is the executable.
- Treating Git as the hypothesis graph. The commit does not keep the losing trial or the motive that was never written.
- A second `seed` in the same campaign. The campaign already has an origin. The path is `record` from the parent.
- Rejecting because another hypothesis dominated. That records a motive nobody gave.
- Merging two incomparable hypotheses, or relinking loose seeds, so the frontier has a single winner.
- Using `spend` as a budget, a frontier metric, or a lock on `record`. Inventing a token count.
- Believing the latest `score` erases the previous one, or mixing `tests_passed` from one trial with `latency_ms` from another.
- Reading `.gitignore` as the scan policy. The explicit policy is `.acvcignore`.
- A hardlink between trees. A symlink inside the seeded folder.
- `promote` as a merge, or `push`/`fetch` while expecting a checkout on the other side.
- Showing a hash, an edge, or "left/right" to the person. The sentence is the premise and which one stays.
- Pasting every cause into one campaign need when the graph has more than one cause.
- Rewriting an already recorded hypothesis to "fix" the premise. A new premise is `revise_premise` or `record`, another node.
- Starting `acvc web` or `acvc tui` from inside the agent session when the person already has the viewer open. Give them the command for their terminal.
